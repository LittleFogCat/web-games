# Baseline 0.14.5-dev — 平衡性调整

> 状态：in_progress  
> 基线版本：0.14.5-dev  
> 依赖：0.14.4-dev（已验收、已部署）  
> 计划周期：1–2 周  
> 最后更新：2026-10-29

## 1. 目标

基于 0.14.4 基线做一轮**数据驱动的平衡调整**；不新增机制、模式、塔或地图。

## 2. 范围

- 用 `vector-td/tools/sim-headless.js` 跑基线矩阵：`none / econ / full` 技能档，L1–L10，`prism / gatling / mixed` 策略。
- 识别四类问题：
  1. 统治策略（单塔/单流派能否平推）；
  2. 关卡尖刺（哪几波、哪几关异常难/易）；
  3. 塔/技能的投入产出比（DPS/晶元、升级阶梯）；
  4. 经济盈余/缺口（晶元过多导致无取舍，或过少导致无解）。
- 只改 `src/config.js` 的数值/曲线：塔伤害/费用/射程/冷却、敌人抗性/生命、波次成长、经济参数。
- 每次只改一个维度；至少跑 L4 / L7 / L9 / L10 四个采样关。
- 同步单位图鉴、游戏策划文档、README 的相关表格。
- 版本 `0.14.5-dev`、`BUILD`、`?v=`、`dist`、`release`、部署与线上验证。

## 3. 候选调整轴（按数据决定，不预设结论）

- **【用户指示，已纳入范围】控制机制重做**：移除"霸体"（完全免疫减速），新增"韧性"——按比例减免减速与击退（铁壁 80%、终焉棱镜 100%）；震荡塔新增击退（0.30–0.50 格，韧性缩短，每敌 0.9s 击退冷却，核心周围 1.6 格免疫区）。起因：震荡 / 冰塔 / 闪电 / 重炮收益过低（DPS/晶元 0.06–0.17 vs 棱镜 0.87），且控制对后期霸体单位完全归零。涉及 `config.js`（特性定义、敌人 tenacity、震荡 knockback）、`game.js`（_applySlow 韧性减免、_applyKnockback）、`render.js` / `app.js`（韧性视觉、简报、详情面板）、图鉴与策划文档。
- 棱镜 / 机炮的投入产出与 IV 级齐射曲线；0.14.1 模拟认为"机枪铺场、棱镜 IV/V 接管"是健康节奏，除非新数据推翻。
- 动能 / 能量对护盾的剪刀差（当前 ×0.45 / ×1.9）与物免/魔免分布。
- 灯塔的 60 + 125 晶元投入是否值得一个塔位。
- `WAVE_HP_GROWTH`、`lateWaveHp`、`lateWaveSpeed` 与中盘压力。
- 升级阶梯（`UPGRADE_COST_MULTIPLIERS`）与技能经济（金币收入/技能成本）。
- 只选 2–3 个轴，不一次全改。

## 4. 验收标准

- 无技能 L1–L3 通过；L4 起失败（符合既有验收表）。
- 满技能 L10 通过，允许 0–40% 完整度损失，不无伤碾压。
- 不存在“单塔/单流派平推全战役”的统治策略；至少 3 种可通关 build。
- 十关总有效 HP 与总收入相对 0.14.4 变动有明确理由；除非有意，控制在 ±10%。
- 3 星曲线不被抹平；手机三尺寸、60fps、控制台无错误。
- 旧存档可迁移；构建 / 发布 / 部署 / 线上 BUILD 验证通过；无 `U+FFFD`。

## 5. 工作顺序

1. 跑 0.14.4 基线模拟，保存“调整前”矩阵。
2. 从数据里选 1 个最明确的异常，提出 1 个最小改动。
3. 只改这个变量，重跑 L4/L7/L9/L10 + 全战役。
4. 对比调整前后：通关率、完整度、HP/收入、塔伤害占比。
5. 通过后手测 3 局；再进入下一个轴。
6. 全部通过后更新文档、版本、构建、部署；在基线文档与日志标记 `accepted`。
