## 1. 状态定义

| 状态 | 含义 |
| --- | --- |
| `planned` | 已排期，未开始 |
| `in_progress` | 正在开发 / 验收 |
| `blocked` | 有明确阻塞，不能继续 |
| `accepted` | 验收通过，可进入下一基线 |
| `archived` | 历史基线，仅留档 |

同一时间只允许 **一个** `in_progress` 基线。`accepted` 之前不启动下一基线；紧急修复走 patch 版本并登记。

## 5. 更新规则

1. **开始任务前**：先读当前基线文档与本日志；只做基线“范围”内的事。
2. **进展变化**：更新对应基线文档的“完成记录”，再更新本日志的进度与“最后更新”。
3. **范围变化**：先改基线文档与本日志，再写代码；禁止代码先行、文档后补。
4. **验收**：基线文档“验收标准”全部通过，才能标记 `accepted`；未通过只能 `in_progress` 或 `blocked`。
5. **版本**：每个 `accepted` 基线必须完成版本号、`BUILD`、`?v=`、`dist`、`release`、部署与线上验证。
6. **不跳级**：未验收不启动下一基线；紧急修复单独开 patch 基线并登记。
