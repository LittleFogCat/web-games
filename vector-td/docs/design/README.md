## 评审流程

关卡与数值不是单人拍板，按以下顺序过评审：

1. **关卡草案**：关卡设计师写清地形意图、波次要问的问题、机制递进，产出[关卡策划](关卡策划.md)变更。
2. **数值复核**：数值设计师用预算/TTK/经济表检查“这波是否打得动、收入是否支撑、是否有唯一解”，产出[数值策划](数值策划.md)变更。
3. **系统复核**：系统设计师检查特性、控制/韧性、伤害通道与 UI 信息是否支持该玩法。
4. **主策/制作人签字**：确认符合当前基线与目标玩家，才进入开发基线。
5. **实现后回归**：无头模拟 + 手测 + 手机三尺寸；结果回写文档与基线日志。

每次提案必须写清三件事：**设计意图 → 预期玩家行为 → 验证指标**。只写“数量/数值”而没有意图的改动，不进入基线。

## 维护规则

1. **单一职责**：总案写基准，关卡写内容，数值写公式与表格，图鉴写单位数据；同一信息只在一个文档维护，其他文档用链接。
2. **先意图后数字**：任何数值/关卡改动，先写清“为什么”，再改表；改完同步对应文档与基线日志。
3. **版本计划不进入总案**：版本路线、变更历史、排期只写在 `docs/baseline/`；总案只保留当前基准。
4. **基准版本变更**：更新 `baseline_<version>.md` 与 `baseline_log.md`，再同步本目录文档；验收通过前不把新内容写成“当前基准”。
5. **过期内容**：历史调参/版本变更移到对应 baseline 文档；总案、关卡、数值只保留当前有效口径。
6. **编码**：所有文档 UTF-8；改完检查 `U+FFFD` 为 0，不要用 PowerShell `Get-Content | Set-Content` 改中文文件。

## 当前基准边界

- 当前基线：**0.14.5-dev（平衡性调整）**。
- 当前基准只含**经典战役**：10 星区、14–20 波、7 攻击塔 + 灯塔 + 壁垒、三大伤害通道、9 种敌人特性。
- 潮汐/超载/无限/元素星域/光环/天赋预设/升阶/融合均为**扩容提案**，不属于当前基线；实现前先立对应 baseline。
