# 复盘系统（内部）

> 性质：调试 / 关卡设计工具，**不向玩家开放**  
> 入口：调试面板顶部「复盘」按钮，或本地 `review.html?debug=1`  
> 关联：[闯关记录](验证记录_三档玩家.md) · [Chrome Local Storage 提取](records/chrome-localstorage.md) · [baseline_0.14.5](baseline/baseline_0.14.5.md)

---

## 1. 它解决什么

手动实测和自动化测试都会产出闯关记录，但此前的记录只能导出 JSON / 用脚本看。复盘系统把同一份数据放进一个独立网页：

- **数据呈现**：关卡 / 结果 / 核心 / 用时 / 击杀 / 漏怪 / 晶元 / 金币 / 技能；逐塔伤害、护盾伤害、击杀与 DPS；真实游戏渲染的 9×16 战场；建造 / 升级 / 回收时间线；逐波核心与晶元曲线；漏怪明细。
- **实时重现**：最新一局带逐秒帧（敌人位置 / 血量 / 护盾 / 隐匿 / 核心 / 晶元），战场直接复用游戏渲染器，可在战场上播放、暂停、1×/2×/4×、拖动进度；旧记录没有逐帧数据时退化为“波次 + 建造时间线”的粗回放。

入口不放进玩家流程：只有调试面板显示「复盘」按钮；直接打开页面时，非本地环境且没有 `?debug=1` 会被拦截页挡住。

## 2. 打开方式

```text
本地：http://127.0.0.1:5180/vector-td/review.html?debug=1
或：游戏内调试面板 → 顶部「复盘」
```

页面使用相对路径加载 `src/util.js`、`src/config.js`、`src/pathgrid.js`、`src/render.js`，不需要构建。

## 3. 数据来源

### 3.1 手动 / 调试对局

每局结算写入 `localStorage['vector_geotd_records_v1']`（最多 100 条，最新在前）。新增字段：

- `replay.frames`：逐秒帧，`{t, w, hp, cr, k, l, e}`；`e` 是敌人数组 `[typeIndex, x, y, hp, maxHp, shield, stealth, revealed, enemyId]`（`enemyId` 用于相邻帧插值；旧帧没有该字段时按类型 / 最近坐标匹配）。
- 采样：战斗时间每 1 秒一帧，单局最多 900 帧、每帧最多 80 个敌人；第一帧在开波时。
- **只保留最近一局的 `replay`**；旧记录自动删掉 `replay`，保留聚合字段。localStorage 写入失败时先丢掉所有 `replay` 再重试，避免整条记录丢失。

### 3.2 自动化测试

```powershell
# 导出某一局（默认 extreme 阵容、ace 技能）
node vector-td/tools/export-replay.js --level=7 --out=tmp/replay-L7.json
node vector-td/tools/export-replay.js --level=10 --comp=mixed --lasers=5 --skills=ace --out=tmp/replay-L10.json
```

导出的 JSON 为 `{kind:'vector-replay', record:{...}}`；在复盘页点「导入 JSON」选择文件即可，导入的记录只存在当前页面内存（不写 localStorage），侧栏带「导入」标记。

`sim-headless.js` 的 `runLevel` 同步返回 `replay / buildLog / towerRecords / waveStats / leakLog`，供其他脚本复用。

## 4. 页面结构

| --- | --- |
| 顶部 | 「导入 JSON」「刷新本地记录」、对局数 |

| 建造 / 升级 / 回收 | 时间、波次、动作、设施、等级、坐标、费用 |
| 漏怪 | 时间、波次、敌人、核心伤害、剩余核心 |

## 5. 回放实现

- 逐帧模式：按 `t` 二分查找当前帧；相邻帧之间按敌人 `id`（旧帧按类型 + 最近坐标）做位置插值，敌人移动是平滑的，不是每秒跳一格。
- 敌人朝向由相邻帧位移计算（`atan2(dy, dx)`）；渲染器的多边形有一个固有 90° 偏移，所以复盘中额外传 `bodyAngle = 运动角 − π/2` 让形体鼻尖对齐运动方向，拖尾仍用运动角。路径回弯 / 向上路段不会看起来“倒着跑”。
- 区间内消失的敌人（死亡 / 漏怪）保留在起点帧位置，不会在 f0→f1 的整秒里提前消失；新出现的敌人按 f1 位置绘制。
- **战场直接用 `src/render.js` 的 `GameRenderer` 绘制**：真实星空背景、流动路径、障碍岩体、五级塔体、灯塔光环、敌人特性视觉、核心与受击光效；复盘页不再自绘示意图。
- 旧记录模式：用 `waves` 的起止核心 / 晶元 + `buildLog` 时间线生成合成帧；战场仍用真实渲染器，只是没有敌人。
- 塔的状态由 `buildLog` 按 `t` 重建：建造加入、升级改等级、回收移除；没有 `buildLog` 时用最终 `towers` 的非回收塔。
- 路径按当前塔 / 壁垒实时重算（`BattleGrid.buildField`），所以回放中壁垒改变路径时能看到路线变化。
- 帧里没有弹道 / 粒子 / 飘字，回放不伪造这些；塔、敌人、核心、路径、背景是真实渲染。
- **旧记录补帧**：没有 `replay.frames` 时，战斗区会显示警告条和「重新模拟」按钮；点击后用记录里的 `buildLog` + 技能在浏览器内跑一遍真实 `Game`（`captureReplay`），生成近似逐帧数据。RNG 与原始局不同，顶部会标注“重模拟回放（近似）”，不能当作原始战斗的精确位置。

## 6. 边界与隐私

- 仅调试 / 本地环境可用；页面不进入玩家导航、首页和游戏 HUD。
- 记录与回放只存在浏览器本地，不上传服务器；导入的记录只在当前标签页内存中。
- 逐帧数据体积：约 1 MB / 局（900 帧上限），因此只保留最近一局；需要长期保存时在调试面板导出 JSON。
- 旧记录（没有 `replay.frames`）仍可看全部数据与粗回放，不会报错；可点「重新模拟」生成近似逐帧（见 §5）。
- 「重新模拟」是按建造记录重跑，不是原始战斗的精确回放；RNG、速度浮动会带来位置 / 时间差异。
- 复盘页只读：不提供改档、加金币、跳关等能力。

## 7. 验证

- `tools/verify-review` 不属于正式工具；回归用 Playwright：进入 L7 → 建塔 → 开波 → 结束 → 记录里有 `replay.frames` → 复盘页列出、选局、伤害 / 建造 / 画布、播放推进、控制台无错误、390 宽无横向溢出。
- 自动化导入：`export-replay.js --level=7` 导出 816 帧，导入后侧栏 1 局、12 行塔伤害、816 帧逐秒回放、播放推进。
- 真实渲染：导入 816 帧，跳到 487s（W11、41 个敌人），`GameRenderer` 绘制真实星空 / 路径 / 塔 / 敌人 / 核心，控制台无错误；L9 旧记录（无逐帧）仍用真实渲染器绘制塔 / 路径 / 核心。
