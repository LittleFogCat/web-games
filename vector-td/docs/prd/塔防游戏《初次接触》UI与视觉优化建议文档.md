# 塔防游戏《初次接触》UI 与视觉优化建议文档

基于关卡「初次接触」（第 3/12 波）运行截图的评审 · 版本 v1.0

## 1. 评审概述

当前界面已经具备统一的科幻极简风格：深蓝底色、青色发光线条、多面体塔造型，整体氛围成立。主要问题不在风格，而在**信息层级与对比度**：几乎所有元素都处于同一低亮度的青蓝色区间，导致关键信息（资源数值、敌人路径、可建造位、主操作按钮）无法第一时间被识别。

本文档将建议分为三个优先级：

- **P0（必改）**：直接影响玩家理解和操作的问题，建议优先排期。
- **P1（应改）**：影响体验完整度和辨识度的问题。
- **P2（打磨）**：提升质感与精致度的优化。

注意：评审依据为静态截图，动画、音效、实际交互逻辑无法确认，文末列出了需要开发者确认的问题。

## 2. 问题总览

- P0-1 顶部 HUD 数值可读性不足
- P0-2 敌人路径几乎不可见
- P0-3 建造按钮不够醒目，信息缺失
- P0-4 障碍物、可建造位、已建造塔之间区分不清
- P1-1 波次进度条与「自动发兵」按钮信息混乱
- P1-2 塔上白色箭头含义不明
- P1-3 缺少攻击范围与塔状态可视化
- P1-4 缺少统一的颜色语义
- P2-1 战斗特效与反馈
- P2-2 字体与排版
- P2-3 界面细节统一
- P2-4 画面布局与空间平衡

## 3. P0：必改项

### P0-1 顶部 HUD 数值可读性不足

**现状**：「核心 68」「73」「波次 3/12」字号偏小，图标、标签、数字三者视觉权重接近，几乎融为一体。这些是玩家战斗中最常查看的信息。

**建议**：

- 数字放大并加粗，标签（核心、波次）降级为小号低亮度文字。
- 核心（生命值）与资源（73）使用不同颜色：核心用青色，资源用琥珀金色。
- 核心数值降低到危险阈值（如低于 30%）时变红并轻微闪烁。
- 数值变化时加入短促的跳动或闪光反馈，并可短暂显示 +N / -N 的变化量。
- 关卡名「初次接触」缩小并降低亮度，把空间让给战斗数据。

**验收标准**：不细看的情况下，一眼能读出当前生命、资源与波次。

### P0-2 敌人路径几乎不可见

**现状**：路径是极细的虚线点阵，和背景网格线、装饰弧线混在一起，玩家需要费力辨认敌人行进路线。

**建议**：

- 将路径做成有宽度的发光通道（宽度约为塔格子的 40%–60%），底色略亮于背景。
- 增加沿路径流动的箭头或光点动画，明确方向。
- 起点（顶部）做出生门特效，例如旋转光环或脉冲；终点核心保留现有圆环并加入呼吸动画。
- 降低背景大圆弧与网格线的对比度，让路径成为地图上的第一视觉层。

**验收标准**：新玩家在 3 秒内能指出敌人的出发点、行进路线与终点。

### P0-3 建造按钮不够醒目，信息缺失

**现状**：底部「建造 3/12」按钮边框很细，且作为核心操作入口，视觉权重低于它应有的程度；「3/12」含义不清晰；看不到费用。

**建议**：

- 提高按钮亮度与面积，使用实心或半实心青色填充，成为画面中最醒目的可点击元素。
- 在按钮上显示建造费用（带资源图标），资源不足时按钮变灰并有抖动提示。
- 「3/12」改为带图标的说明，如「已建 3 / 上限 12」，或在首次出现时给出提示。
- 保证按钮距屏幕底边和边缘有足够安全距离，避免误触；点击热区不小于 44×44 px。

**验收标准**：玩家不需点击就知道建造要花多少、还能建多少。

### P0-4 障碍物、可建造位、已建造塔区分不清

**现状**：障碍物（暗紫色多边形）与塔（青色多面体）外形相近，主要靠颜色区分；障碍物轮廓线很淡，容易被误认为装饰或可交互物。

**建议**：

- 明确三种状态的视觉语言：
  - 障碍物：更暗、无发光、可加裂纹或细节纹理，明确为背景。
  - 可建造位：统一的虚线轮廓或十字标记，进入建造模式时整体高亮。
  - 已建造塔：保持发光，并带底座光环。
- 除颜色外，再增加形状或轮廓差异，照顾色弱玩家与小屏幕场景。
- 点击障碍物时给出明确反馈（如「无法建造」提示），避免玩家反复尝试。

**验收标准**：不依赖颜色也能区分三种对象。

## 4. P1：应改项

### P1-1 波次进度条与「自动发兵」按钮

**现状**：顶部细线进度条对比度和粗细不足；「自动发兵 10s」按钮中倒计时、小标签、进度线、三角箭头挤在一起；右侧「×1」与音量按钮风格较弱。

**建议**：

- 进度条加粗到 3–4 px，末端加发光点，并标出波次分段刻度。
- 倒计时数字放大作为按钮主体，「自动发兵」降为辅助小字。
- 强化「点击可提前发兵」的可交互暗示，例如按钮边缘脉冲或箭头动画，并建议提前发兵时给出奖励反馈。
- 「×1」倍速按钮在加速状态下（×2、×3）切换颜色，让玩家明确当前状态。

### P1-2 塔上白色箭头含义不明

**现状**：三座塔上各有一个白色向上箭头，既像「可升级」，又像「朝向」或「攻击方向」，存在歧义。

**建议**：

- 若表示可升级：使用通用升级图标（如向上的双箭头 / 加号），搭配轻微上下浮动动画，且仅在资源足够时显示。
- 若表示朝向：改用扇形或细线表现，不与升级提示混用。
- 图标颜色与塔本体拉开，同时与全局颜色语义保持一致。

### P1-3 缺少攻击范围与塔状态可视化

**建议**：

- 选中塔时显示清晰的半透明射程圈，边缘用实线，内部淡填充。
- 建造预览阶段（拖动或选中位置时）同样显示射程圈。
- 用轮廓层数、颜色或小标记区分塔的类型与等级；升级后外观应有可感知的变化。
- 选中塔时弹出信息面板：类型、等级、伤害、射速、升级与出售费用。

### P1-4 缺少统一的颜色语义

**建议**：建立全局颜色规范，并在所有界面和特效中严格遵守：

- 青色 `#2EE6D6`：友方、可交互、已建造塔
- 琥珀金 `#FFB547`：资源、金币、奖励
- 红橙 `#FF5A4D`：敌人、危险、生命值告急
- 白色 `#FFFFFF`：选中态、高亮、关键提示
- 深蓝背景 `#070D1A` 与次级面板 `#0F1B2D`：基础底色
- 灰蓝 `#6B7F99`：次要文字、禁用态

以上色值为建议起点，请结合实际素材微调。关键元素（核心、敌人、可点击按钮）的亮度应明显高于背景。

## 5. P2：打磨项

### P2-1 战斗特效与反馈

- 子弹或激光加入拖尾与辉光（bloom）。
- 命中时有闪光与受击抖动；敌人死亡有粒子碎裂效果。
- 核心受到伤害时屏幕边缘红色闪烁，并伴随音效。
- 新一波开始时有醒目的波次提示动画。
- 注意控制特效数量与叠加透明度，避免后期画面过载、遮挡路径。

### P2-2 字体与排版

- 数字使用等宽或几何风格字体（如 Orbitron、Rajdhani），避免数字跳动时宽度变化导致抖动。
- 中文部分使用笔画清晰的黑体，不追求花哨造型，以可读性优先。
- 建立字号层级：主数值、按钮文字、标签、提示，各层级之间有明显差距。

### P2-3 界面细节统一

- 统一一套设计规范：描边粗细（建议 1.5 px）、切角方向与大小、发光强度与半径。
- 当前顶部按钮与底部按钮的切角样式存在细微差异，建议统一。
- 按钮需有完整状态：默认、按下、禁用、选中，并保持一致的动效时长（建议 120–200 ms）。

### P2-4 画面布局与空间平衡

- 当前左上区域塔较密集，中右侧存在较大空白，画面重心偏移。
- 若属于关卡设计问题，可调整障碍物与建造位分布；若属于视觉问题，可用淡色装饰元素、微粒或星云平衡画面。
- 保持路径周围留有足够空间，避免装饰抢夺注意力。

## 6. 实施路线建议

- **第一阶段（约 1 周）**：P0-1 HUD、P0-3 建造按钮、P1-4 颜色规范。这几项成本较低、收益最大，且颜色规范是后续所有改动的基础。
- **第二阶段（约 1–2 周）**：P0-2 路径重做、P0-4 三态区分、P1-1 顶部控制区。
- **第三阶段（约 1–2 周）**：P1-2 与 P1-3 塔的状态与范围显示、P2-1 战斗特效。
- **第四阶段（持续）**：P2-2 至 P2-4 的字体、细节与布局打磨。

每个阶段结束后建议找 3–5 名未接触过游戏的玩家做简短测试，观察其是否能无提示完成：识别路径、建造第一座塔、理解升级提示。

## 7. 需要开发者确认的问题

- 塔上的白色箭头实际表示什么（升级、朝向或其他）？
- 「建造 3/12」中的数字具体含义是什么？
- 顶部细线是波次进度条，还是其他计时？
- 游戏主要运行平台是手机竖屏，还是同时支持平板和桌面？这会影响点击热区与布局。
- 现有的战斗动画与特效有哪些？截图中无法体现。

如果能提供动态录屏或各状态截图（选中塔、建造模式、战斗中、核心受损），可以进一步细化动效和反馈层面的建议。
